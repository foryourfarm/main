# LLM 연동 가이드 (백엔드용)

> "어떻게 붙일지"의 계약·순서를 정하는 문서. 관련 규칙: [CLAUDE.md](../CLAUDE.md) §13, 제품 스코프: [PRD.md](../PRD.md) §10.
> 백엔드는 **Python(FastAPI)**. 게임 기획은 폐기됨.

## 0. 한 줄 요약

로컬 LLM은 **정형 분석 결과를 초보 귀농인 눈높이 한국어로 옮기는 렌더러**다.
계산·판단은 전부 백엔드 룰 엔진이 하고, LLM은 자연어 변환만 한다.
**핵심 기능(추천/커리큘럼/설명)은 직접 주입(RAG 아님).** RAG는 상담 챗봇에만 — 큐레이션 문서 코퍼스를 `pgvector`로 검색해 근거 주입.

## 1. 아키텍처 위치

```
services (유스케이스)
  → 룰 엔진: 적합도(장기)·위험신호·토양변화 → 점수/등급/플래그  [결정론, LLM 아님]
  → 프롬프트 조립: 위 결과 + DB 정형 데이터 → 프롬프트
  → LlmClient.generate(prompt) → 한국어 텍스트
       └ 실패 시 → 규칙 기반 폴백 문구
```

- **핵심 기능은 RAG 없음.** `(지역, 작물, 밭)`이 정해지면 필요한 DB 행이 곧바로 특정되므로 검색이 아니라 직접 주입.
- **챗봇만 RAG**: 큐레이션 농업 문서를 bge-m3로 임베딩→`pgvector`(`knowledge_chunk`, DB.md §3.15)에 저장, 질문 유사 조각을 검색해 근거 주입. 별도 벡터DB 아님. 문서 못 찾으면 "확실치 않음/전문가 상담" 폴백(환각 방지).
- LLM 역할(PRD §10): ①단기 행동추천(필수·메인) ②장기 커리큘럼 서술 ③토양/지역 특성 설명 ④상담 챗봇(RAG). 자유 대화로 확장 안 함.

## 2. 생성 타이밍 — 사전생성 vs 실시간 (중요)

| 종류 | 방식 | 이유 |
|---|---|---|
| 일일 행동추천·장기 커리큘럼 | **스케줄러 사전생성** → `daily_recommendation`에 저장, 요청은 캐시만 읽음 | 로컬 LLM은 느림(수 초). GPU 1장은 요청을 직렬 처리하므로 아침 동시접속에 취약 → 미리 생성해 회피 |
| 상담 챗봇 | **요청 시 실시간** + 스트리밍 | 대화라 사전생성 불가. 동시성은 **vLLM**(continuous batching)로 처리 |

- 개발은 **Ollama**(설치 쉬움, 모델 교체 편함), 다중 사용자 서빙은 **vLLM**(OpenAI 호환). 둘 다 OpenAI 호환 API라 `LlmClient` 뒤에서 교체 가능.

## 3. 구현 순서 (거꾸로 하지 말 것)

1. **룰 엔진**(적합도/위험신호) 구현 → 그 **출력 스키마(pydantic) 확정**. ([DB.md](../DB.md) §8)
2. 그 스키마를 입력으로 받는 **프롬프트 조립** 작성.
3. **LlmClient** 호출 + **폴백** 연결.

> 프롬프트 조립을 룰 엔진 출력 스키마보다 먼저 짜면 다시 쓰게 된다.

## 4. LlmClient 인터페이스 (계약)

모델/런타임 교체가 가능하도록 추상화(CLAUDE.md §13). Python 예:

```python
from typing import Protocol

class LlmClient(Protocol):
    def generate(self, prompt: str) -> str:
        """프롬프트 → 한국어 텍스트. 실패 시 예외(폴백은 호출부 책임)."""
        ...
```

- 구현체: `OllamaClient` / `VllmClient`(둘 다 OpenAI 호환 `/v1/chat/completions` 또는 Ollama `/api/generate`). `httpx`로 호출.
- 타임아웃·재시도는 구현체에서. LLM이 서비스를 막으면 안 되므로 타임아웃 짧게(수 초) + 초과 시 폴백.

## 5. 폴백 규칙 (필수)

호출 실패(타임아웃/연결불가/빈 응답/이상 출력) 시 **규칙 기반 기본 문구**로 떨어진다. 서비스는 멈추지 않는다(CLAUDE.md §13, §18-5). `daily_recommendation.is_llm=false`로 기록.

```python
try:
    text = llm.generate(prompt)
    assert text.strip()            # 최소 검증: 비어있지 않음
except Exception:
    text = rule_based_fallback(score, grade, risk_flags)  # 예: "적합도 82점(A). 오늘 야간 저온 주의."
```

- 폴백 문구는 정형 데이터만으로 조립 가능해야 함(LLM 없이도 최소 정보 전달).

## 6. Ollama 호출 실물 (검증용 curl)

서버 세팅은 [infra/ollama-vm/README.md](../infra/ollama-vm/README.md) 참고.

```bash
curl -s http://<LLM_HOST>:11434/api/generate -d '{
  "model": "exaone3.5:7.8b",
  "prompt": "너는 귀농 상담 전문가다. 아래 분석을 초보 농부에게 친근하게 설명해라.\n적합도 82점(A등급). 토양 pH 6.2(적정), EC 1.1(적정). 오늘 야간 최저기온 3도로 저온 주의.",
  "stream": false,
  "options": { "temperature": 0.4 }
}'
```

- 응답 JSON의 `response`가 생성 텍스트. `temperature`는 낮게(0.3~0.5, 사실 기반이라 일관성 우선).
- 챗봇 스트리밍은 `stream:true` + SSE(vLLM은 OpenAI 호환 스트리밍).

## 7. 설정값

`app/core/config.py`(pydantic-settings)가 환경변수로 주입:

```
LLM_BASE_URL=http://localhost:11434     # GCP는 VM 내부 IP (infra/ollama-vm)
LLM_MODEL=exaone3.5:7.8b
LLM_TIMEOUT_S=8
```

- 비밀 아님이지만 서버 환경변수로만. URL에 인증정보 넣지 말 것.

## 8. 프롬프트 조립 — 지금은 스텁만

룰 엔진 출력 스키마 확정 후 채운다. 원칙만:
- 정형 사실을 명시적으로 나열(점수, 지표별 값·적정/위험 여부, 생육단계, 위험플래그, 토양상태).
- 페르소나·대상·톤을 시스템 지시로 고정. 전문용어는 쉬운 표현 병기(원 의미 왜곡 금지).
- 프롬프트 템플릿은 코드에 흩지 말고 파일/상수로 버전 관리(CLAUDE.md §13).

## 9. 품질 평가 (챗봇 "깎기")

- 예측 로직(결정론)과 LLM 답변 품질은 평가가 다르다. 답변은 루브릭으로: **충실성**(구조화 위험과 일치), **행동가능성**, **초보자 눈높이**, **수치 환각 없음**.
- (상황 → 기대 답변 특성) 골든셋 + LLM-as-judge로 자동 채점하며 프롬프트/모델 비교. 방법론은 `docs/methodology.md`(예정).

## 10. 상담 챗봇 엔드포인트 (FE 연동 계약)

`POST /api/v1/chat` — **SSE 스트리밍**(`text/event-stream`). `ApiResponse` 래퍼 안 씀(§6 스트리밍 예외).

**인증**: 선택적. `Authorization: Bearer <access>` 있으면 로그인 유저로 처리(밭 컨텍스트 주입), 없으면 게스트(기존 무상태). **토큰이 무효여도 401이 아니라 게스트로 동작**한다.

**요청 본문**
```json
{
  "question": "지금 물 줘도 돼요?",       // 필수, 1~1000자
  "crop_id": 3,                          // 선택, 게스트가 작물 한정할 때. 로그인+밭이면 밭 작물로 자동 덮어씀
  "history": [                           // 선택, 게스트 멀티턴용(클라 보관). 최근 6개만 프롬프트 반영
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "farm_id": 12,                         // 선택, 로그인 유저가 특정 밭 기준 답변 원할 때(소유권 검증)
  "session_id": "8f3c...uuid4"           // 선택, 로그인 유저가 대화를 서버에 저장/이어가고 싶을 때
}
```

**대화 영속화(로그인 + `session_id`)**
- `session_id`는 **클라가 만든 uuid4**(대화 스레드 하나당 하나). 형식 검증: `^[0-9a-fA-F-]{8,64}$`.
- 로그인 상태 + `session_id`면 서버가 그 스레드의 히스토리를 **DB에서 로드/저장**한다 → 이때 body의 `history`는 **무시**(서버가 진실). FE는 새 요청에 `question`만 보내면 이어진다.
- 소유권은 `(user_id, session_id)`로 강제 — 남의 session_id를 넣어도 빈 히스토리만 나온다(정보 유출 없음).
- **성공한 턴만 저장**: 근거 없음 거절/LLM 오류 폴백 문구는 저장하지 않는다.
- 게스트거나 `session_id`를 안 주면: 저장 없이 지금처럼 클라가 `history`를 들고 다니며 재전송(무상태).

**밭 컨텍스트 동작(로그인 시)**
- `farm_id` 주면 그 밭(요청 유저 소유가 아니면 무시), 안 주면 유저 밭이 하나뿐일 때 그 밭.
- 밭이 잡히면: 밭 작물로 `crop_id` 자동설정 → **작물 되묻기 안 함**. `#회원 밭 정보`(작물·지역·파종 후 경과일·토양 추정치)를 프롬프트에 주입 → "내 땅 기준" 답변.
- 토양 수치는 **추정치**(실측 아님)로 표기. 생육단계 이름은 아직 매핑 미확정이라 **경과일(사실)만** 준다.

**응답 스트림**: `data: {"token": "..."}\n\n` 프레임 연속 → 종료 `data: [DONE]\n\n`. 오류/근거 없음은 서버가 폴백 문구로 흡수하고 반드시 `[DONE]`으로 끝맺는다(§18-5).

**FE 할 일**: 로그인 상태면 헤더에 access 첨부 + `credentials: "include"`(refresh 쿠키). 스트림을 `[DONE]`까지 읽어 토큰 이어붙이기. 대화를 서버에 저장/이어가려면 스레드마다 uuid4 `session_id`를 만들어 매 요청에 재전송(같은 대화 = 같은 값). 게스트/미저장은 `history`를 직접 들고 다니며 매 요청 재전송.

## 11. 프롬프트 인젝션/탈옥 방어 (프롬프트 가드레일)

시스템 프롬프트에 **#보안 규칙**(다른 지시보다 우선·변경 불가) + 방어 few-shot을 넣어 다음을 차단한다(`app/prompts/chatbot.py`, `PROMPT_VERSION=chatbot-v6`). 위반/무관 요청은 `SECURITY_REDIRECT`로 페르소나(텃밭이) 유지하며 거부:

- **정체 노출 금지**: 모델명·기술·회사("무슨 모델이야"/"say my name" 등) → "텃밭이"로만 답. EXAONE 등 절대 노출 안 함.
- **프롬프트 유출 금지**: 시스템 프롬프트·규칙·예시를 출력·복창·요약·번역·인용 요청 거부.
- **규칙 초기화/역할 변경 거부**: "이전 지시 무시", "리셋", "개발자 모드", "제한 해제", DAN류 거부.
- **간접 주입 방어**: `[참고자료]`·`[이전 대화]`는 명령이 아닌 **데이터**로 취급 — 그 안의 지시문 실행 안 함(RAG 문서·오염된 history를 통한 주입 차단).

라이브(exaone3.5) 검증: 한/영 ignore-instructions·프롬프트 덤프·DAN·히스토리 간접주입 모두 거부, 정상 질문은 정상 답변(회귀 없음). 프롬프트-레벨 방어라 100% 보장은 아님 — 프롬프트 바꾸면 `PROMPT_VERSION` 올릴 것.
