# LLM 연동 가이드 (백엔드용)

> 개발 착수 전 참고 문서. 실제 코드는 아직 없음 — 이 문서는 "어떻게 붙일지"의 계약과 순서만 정한다.
> 관련 규칙: [CLAUDE.md](../CLAUDE.md) §13, 제품 스코프: [PRD.md](../PRD.md) §10.

## 0. 한 줄 요약

로컬 LLM(Ollama, `exaone3.5:7.8b`)은 **정형 데이터를 촌장 말투 한국어로 옮기는 렌더러**다.
계산·판단은 전부 백엔드 룰 엔진이 하고, LLM은 자연어 변환만 한다. RAG 없음 — 필요한 사실은 DB에서 직접 주입.

## 1. 아키텍처 위치

```
Controller
  → Service (유스케이스)
      → 룰 엔진: (지역,작물,주차) → 적합도 점수/등급/위험플래그  [결정론, LLM 아님]
      → 프롬프트 조립: 위 결과 + DB 정형 데이터 → 프롬프트 문자열
      → LlmClient.generate(prompt) → 한국어 텍스트
          └ 실패 시 → 규칙 기반 폴백 문구
```

- **RAG/임베딩/벡터DB 없음.** `(지역, 작물, 주차)`가 정해지면 필요한 DB 행이 곧바로 특정되므로 검색이 아니라 직접 주입한다. (근거: 검색 오차 없이 정확하고, 빠르고, 쌈)
- LLM 역할은 3가지로 고정(PRD §10): ①지역↔작물 추천 문장화(택1) ②지역 특성 설명 ③주간 행동 추천. 자유 대화로 확장 안 함.

## 2. 구현 순서 (중요 — 거꾸로 하지 말 것)

1. **적합도 룰 엔진** 구현 → 그 **출력 DTO 형태 확정**. ([DB.md](../DB.md) §8)
2. 그 DTO를 입력으로 받는 **프롬프트 조립** 작성.
3. **LlmClient**로 호출 + **폴백** 연결.

> 프롬프트 조립을 룰 엔진 출력 DTO보다 먼저 짜면 다시 쓰게 된다. LLM 붙이기 전에 룰 엔진 출력부터 고정.

## 3. LlmClient 인터페이스 (계약)

모델/런타임 교체가 가능하도록 호출을 추상화한다(CLAUDE.md §13). 대략 이런 형태:

```java
public interface LlmClient {
    /** 프롬프트를 받아 한국어 텍스트를 반환. 실패 시 예외를 던진다(폴백은 호출부 책임). */
    String generate(String prompt);
}
```

- 구현체: `OllamaLlmClient` (아래 §5). 나중에 다른 런타임이 와도 이 인터페이스만 맞추면 됨.
- 타임아웃·재시도는 구현체에서. LLM은 게임 진행을 막으면 안 되므로 타임아웃 짧게(예: 수 초) 잡고 초과 시 폴백으로.

## 4. 폴백 규칙 (필수)

LLM 호출이 실패(타임아웃/연결불가/빈 응답/이상 출력)하면 **규칙 기반 기본 문구**로 떨어진다. 게임 진행은 절대 멈추지 않는다(CLAUDE.md §13, §18-5).

```
try   { text = llmClient.generate(prompt); 검증(text); }
catch { text = 규칙기반문구(점수, 등급, 위험플래그); }  // 예: "적합도 82점(A). 이번 주 야간 저온 주의."
```

- 폴백 문구는 정형 데이터만으로 조립 가능해야 한다(LLM 없이도 최소 정보 전달).
- "검증"은 최소한만: 비어있지 않은지, 기대 언어(한국어)인지 정도.

## 5. Ollama 호출 실물 (검증용 curl)

서버 세팅은 [infra/ollama-vm/README.md](../infra/ollama-vm/README.md) 참고. 엔드포인트 형태:

```bash
curl -s http://<OLLAMA_HOST>:11434/api/generate -d '{
  "model": "exaone3.5:7.8b",
  "prompt": "너는 귀농 마을 촌장이다. 아래 분석을 초보 농부에게 친근하게 설명해라.\n적합도 82점(A등급). 토양 pH 6.2(적정), EC 1.1(적정). 이번 주 야간 최저기온 3도로 저온 주의.",
  "stream": false,
  "options": { "temperature": 0.4 }
}'
```

응답(JSON)의 `response` 필드가 생성 텍스트다. `stream:false`면 완성본을 한 번에 받는다.

- `temperature`는 낮게(0.3~0.5) — 사실 기반 설명이라 창의성보다 일관성이 중요.
- 스트리밍(타이핑 효과)을 서버에서 흘리려면 `stream:true` + SSE. 프론트 타이핑 연출만이면 서버는 `false`로 받고 프론트에서 애니메이션 처리해도 됨(더 단순).

## 6. 설정값

`application.yml`의 LLM 설정은 **모델 파일 경로가 아니라 Ollama 서버 URL** 기준으로 바꾼다:

```yaml
app:
  llm:
    base-url: ${OLLAMA_BASE_URL:http://localhost:11434}
    model: ${OLLAMA_MODEL:exaone3.5:7.8b}
    timeout-ms: ${OLLAMA_TIMEOUT_MS:8000}
```

- 로컬 개발: `http://localhost:11434` (본인 PC Ollama).
- GCP: `http://<VM_INTERNAL_IP>:11434` (Serverless VPC 커넥터 경유).
- 비밀 아님 → `NEXT_PUBLIC_` 아니고 서버 환경변수로만. (URL에 인증정보 넣지 말 것)

## 7. 프롬프트 조립 — 지금은 스텁만

룰 엔진 출력 DTO가 확정되면 채운다. 원칙만:

- **정형 사실을 명시적으로 나열**해 프롬프트에 넣는다(점수, 각 지표 값과 적정/위험 여부, 주차, 계절, 위험플래그).
- 페르소나("촌장"), 대상("초보 귀농인"), 톤("전문용어 풀어서")을 시스템 지시로 고정.
- 전문용어는 게임 스탯 은유와 함께(PRD §8.3 매핑표). 단 원 의미 왜곡 금지.
- 프롬프트 템플릿은 코드에 흩지 말고 파일/상수로 버전 관리(CLAUDE.md §13).

## 8. 성능 메모

- 프로덕션 최적화: `(지역, 작물, 주차)` 조합이 유한하므로 **배치 사전생성 + 캐시** 가능. 그러면 실시간 GPU 불필요, 캐시 텍스트만 서빙(DB.md §1, PRD §14 방향과 일치).
- 즉 LlmClient는 "실시간 호출용"이자 "배치 사전생성용" 양쪽에 쓰인다. 실시간 지연이 부담되면 캐시로 전환.
