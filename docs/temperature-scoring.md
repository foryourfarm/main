## 1. 왜 기온이 이렇게 복잡한가

기온은 우리 제품에서 **두 번 쓰인다**.

- **장기 탭**: 월별 평년 기온 → 그 달의 생육단계 밴드와 비교 → 12칸 히트맵
- **단기 탭**: 단기예보 일값 → 같은 밴드와 비교 → 날짜별 위험신호

그리고 문제정의서가 지목한 실패 사례(A씨 — 봄철 야간 저온으로 활착 실패)가 정확히 기온
지표다. **PR #68 이전에는 `temp_night_min_normal`이 전 행 NULL이어서 그 지표를 아예 채점하지
못했다**(0행 → 1,668행).

## 1-1. 표시하는 기온과 채점하는 기온이 다르다 (2026-08-04, 0032)

**단기 탭 카드의 "낮 기온"은 실제로 낮 기온이 아니었다.** `fold_daily()`가 `fcstTime`을 읽지도
않고 그날 `TMP`(1시간 기온) 전부를 산술평균한 값을 그 자리에 띄우고 있었다. 실측 대조:

```
2026-08-04 14시 발표, 순천 70,70
  일평균 31.3℃   일최고 38℃    ← 6.7℃ 차이. 유저는 31.3을 "낮 기온"으로 봤다
  일평균 29.2℃   일최고 36.0℃  (+1일)
```

그래서 역할을 분리했다.

| 역할 | 값 | 어디에 |
|---|---|---|
| **표시** | `temp_max` 일최고 | 카드 "낮 최고기온", 모달 마커 |
| **표시** | `temp_night_min` 일최저 | 카드 "야간 최저" |
| **채점** | `temp_avg` 일평균 | 지표 `temp_day` 입력. **밴드·채점 로직 무변경** |

**채점을 건드리지 않은 이유**: 밴드들이 서로 다른 척도의 혼합이라(§8-1) 어느 관측값으로 바꿀지
자체가 미결정이다. 근거를 모르는 상태에서 밴드를 재해석하는 것은 §3-2 위반이다.

지표 표시명은 `"낮 기온"` → **`"일 평균기온"`**으로 바꿨다(BE·FE 양쪽 `INDICATOR_NAMES`).
안 바꾸면 경고 문구("낮 기온이 31.3℃로 허용 범위를 벗어납니다")가 카드 숫자(38℃)와 정면
모순된다.

### 단기 탭 데이터 경로 (§2는 장기 경로만 그린다)

```
기상청 단기예보 getVilageFcst
   │ TMP(1시간 기온) · TMX(일최고) · TMN(일최저) · PCP · POP · REH
   ↓ fold_daily()  — 날짜별로 접는다
   │   temp_avg  = mean(그날 TMP 전부)        ← 채점 입력
   │   temp_max  = TMX, 없으면 max(TMP)       ← 표시
   │   temp_night_min = TMN, 없으면 min(TMP)  ← 표시 + 채점
   │   hourly_temp = [{h, t}, …]              ← 모달 그래프
   │   is_partial = 앞결손 or 뒤결손
   ↓ weather_snapshot (region, kind, base_at, target_date) 캐시
   ↓ forecast_values() — {"temp_day": temp_avg, …}
   ↓ 채점 — 장기 탭과 **같은** crop_growth_guide 밴드·룰 엔진
```

### 첫날 값은 부분 표본이다

실측한 슬롯 구조(같은 호출):

```
        TMP                        TMX      TMN
오늘    n= 9  15~23시  1시간 간격  (없음)   (없음)   ← 발표시각 이후만
+1일    n=24  00~23시  1시간       1500     0600
+2일    n=24  00~23시  1시간       1500     0600
+3일    n= 8  00~21시  **3시간**   1500     0600
+4일    n= 1  00시만               (없음)   (없음)
```

14시 발표면 오늘은 15~23시 9개뿐이라 **새벽·오전이 통째로 빠진다.** 그 표본으로 평균을 내면
일평균이 실제보다 높고, TMX가 없어 `max(TMP)` 폴백이 되는 일최고는 낮 피크를 놓쳐 낮게 나온다.
유저 화면에서 첫날만 값이 튀어 허용상한을 넘고 경고가 떴던 것이 이 편향이다.

`is_partial` 판정은 **표본 개수가 아니라 덮은 시각 범위**로 한다 — 위 표에서 보듯 "온전한
하루"의 표본 수가 24개(1시간)와 8개(3시간)로 갈리기 때문이다. 두 간격 모두 마지막 슬롯이
21시 이상이라 `LAST_SLOT_HOUR = 21`을 기준선으로 쓴다. 저장은 기존 `weather_snapshot.is_imputed`
컬럼을 재사용했다(§12의 "대체됨 플래그"). 화면에는 카드 배지 + `PARTIAL_DAY_LIMITATION`으로
편향 **방향까지** 알린다.

## 2. 데이터 경로

```
① 관측 수집
   1차 농업기상(218지점) — 일사량·일조시간도 여기에만 있다
   2차 기상청 AWS(534지점) — 1차가 없는 구역만
        │ AWS는 일평균을 주지 않아 (max+min)/2 로 근사하고 고정 편향을 뺀다
        ↓
② 지점 → 구역 (ETL 배치)
   k=5 거리가중 + 고도 필터 ±100m + 10km 상한
        ↓
③ weather_climatology  (구역 × 월)
   temp_avg_normal / temp_night_min_normal / reference_altitude_m
        ↓
④ 구역 → 구역 KNN (읽기 시점) — 그래도 비어 있는 구역만
   k=3 거리가중 + 고도 필터 ±100m.  PR #68로 대상이 140개 → 1개
        ↓
⑤ 밭 고도 감률 보정 (읽기 시점)
        ↓
⑥ 3개월전망 tercile 보정 (읽기 시점, 캐시하지 않는다)
        ↓
⑦ 채점 — crop_growth_guide의 (작물, 생육단계, 지표) 밴드와 비교
```

**②가 요청 시점이 아니라 배치인 이유**: 같은 입력이면 같은 출력이어야 하고(§2 결정론),
요청마다 지점을 다시 고를 이유가 없다. 원래 계획은 런타임 폴백이었으나 PR #68에서 바꿨다.

**⑥을 캐시하지 않는 이유**: 캐시에는 시간에 불변인 평년치만 넣고, 시간에 따라 바뀌는 보정은
읽을 때 얹는다. 그러지 않으면 전망이 갱신될 때 캐시가 조용히 낡는다.

## 3. 기온에 걸리는 보정 4개

| 보정 | 값 | 적용 시점 | 근거 |
|---|---|---|---|
| AWS 일평균 근사 | `(max+min)/2 − 0.348℃` | ETL | 13지점·1,592일 실측 대조, R²=0.9959 / MAE 0.518℃ / ±1℃ 이내 89% |
| 관측망 혼용 | **보정 없음** | — | 참 일평균 차이 +0.027℃ = 사실상 0 (127구역·3,533일쌍) |
| 고도 감률 | `(밭 고도 − reference_altitude_m) × 0.65℃/100m` | 읽기 | 환경감률. 20m 미만 차이는 보정하지 않는다 |
| 3개월전망 | `δ × (P상 − P하)/100`, `δ = (similar_high − similar_low)/2` | 읽기 | 기상청 tercile 확률예보 |

### 3-1. AWS 근사값의 근거

`sfc_aws_day.php`가 일평균기온을 주지 않는다 — `obs` 목록에 `ta_max`/`ta_min`만 있고
`ta_avg`/`ta_day`/`ta_mean`은 전부 빈 응답이다(실호출 확인). 일평균을 직접 주는
`getDailyAwsData`는 지점당 1회 호출이라 5년치에 44,400회가 필요하고 월보 기반이라 발간이
2~3개월 늦다. 그래서 근사를 택하고, `getDailyAwsData`의 실제 평균과 대조해 편향을 측정했다.

`(max+min)/2`는 참 일평균보다 체계적으로 높다 — 기온이 밤에 오래 낮게 머물러 중간값이
참평균보다 위로 뜬다. 지형별 편향은 0.197~0.547℃로 갈리지만 전국 단일값을 쓴다: 지점별 잔차
최대 ±0.2℃가 적합도 점수로는 0.18점(100점 만점)이고 등급 컷 간격이 15점이라 등급을 뒤집지
못한다. 값은 코드가 아니라 `docs/seed/aws_temp_calibration.json`에 있다(§18-2).

**이 상수를 재현하는 스크립트가 리포에 없다** — 시드 파일이 지목하는
`scripts/validate_aws_temp_approximation.py`가 git 이력에도 없다. 기존 결함이며
`nexttodo.md` 🟠에 기록돼 있다.

### 3-2. 관측망 혼용에서 남는 편향 하나

일평균은 섞어도 되지만 **일교차는 농업기상이 더 크다**(최고 +0.314℃ / 최저 −0.138℃).
논밭·과수원 개활지라 복사냉각·가열이 강한 것으로 보인다.

> **그래서 AWS로 채운 구역은 야간 저온 위험을 약 0.14℃ 과소평가한다.** 보정하지 않고
> `docs/seed/aws_temp_calibration.json`에 명시만 했다. A씨 사례가 야간 저온이므로 이 방향의
> 과소평가는 인지하고 있어야 한다.

### 3-3. 고도 감률의 기준선이 왜 따로 필요한가

보정은 `밭 고도 − 그 평년치가 대표하는 고도`다. 기준선이 틀리면 보정이 오차를 키운다.
**구역 대표점을 기준선으로 쓰면 안 된다** — 농업기상 114구역에서 관측지점 고도 vs 구역
대표점이 MAE 40m·p90 92m·**최대 370m**(남원시: 지점 474m vs 대표점 104m)다. 370m는 2.4℃라
"보정"이 그만큼 틀어놓는다. 그래서 ETL이 실제로 섞인 지점들의 거리가중 평균 고도를
`weather_climatology.reference_altitude_m`에 행마다 기록한다(남원 318m, 평창 530m).

**감률은 기온에만 적용한다.** 강수·일사는 고도와 이런 단순한 선형 관계가 아니라 같은 식으로
보정하면 없는 값을 지어내는 것이 된다.

실측 효과 — 같은 군 안에서 갈리는 폭:

```
평창군 23.4℃ → 평창읍 주진리(298m) 24.1℃ / 대관령면 횡계리(735m) 21.3℃
남원시 25.4℃ → 금지면(66m) 27.0℃      / 운봉읍(465m) 24.4℃
```

### 3-4. 고도 필터는 기온에만 켠다

기온은 고도가 지배하므로(0.65℃/100m) 거리가 가까워도 고도가 다르면 남의 기후를 빌려온다.
10km 이내 지점쌍 실측(7월 일최고기온):

| 고도차 | MAE |
|---|---|
| 0~50m | 0.98℃ |
| 50~100m | 1.07℃ |
| 200~500m | 2.29℃ |
| 500m 초과 | **5.07℃** |

±100m를 고른 근거는 0~50m와 50~100m의 오차가 거의 같다는 것 — 그 안쪽은 고도차보다 지점
고유 잡음이 더 크다. 서귀포시는 도너 고도 산포가 **1,524m**였다(한라산 지점과 해안 지점이
같은 후보에 든다).

**같은 필터가 일사량에는 역효과다**(구역간 KNN 1.3% 악화, 지점→구역 k=10에서 0.9404 → 0.9937).
고도가 일사량을 기온만큼 지배하지 않는다. 지표마다 물리가 달라 필터를 공유하지 않는다 —
상세는 [`ml/aws-solar-climatology-explainer.md`](./ml/aws-solar-climatology-explainer.md).

## 4. 백엔드 기온 밴드 (현재값)

`crop_growth_guide`의 `temp_day` / `temp_night_min`. 굵은 값은 **문헌 직접 근거**이고,
나머지 `allowed`는 `optimal` 폭 ±50% 휴리스틱이다(§8).

| 작물 | 생육단계 | 지표 | optimal | allowed | 근거 |
|---|---|---|---|---|---|
| 사과 | fruit_growth | temp_day | 18~24 | 15~**31** | 상한 31℃ = LoopReport 고온 임계 |
| | maturity | temp_day | 20~25 | 17.5~27.5 | 농사로 |
| | coloring | temp_day | 12~13 | 11.5~13.5 | 농사로 |
| | coloring | temp_night_min | 8~8 | — | 농사로 |
| 배 | growing | temp_day | **18.5~21.5** | **17~23** | ARCCAS 재배적지(적지/가능지) |
| 오이 | growing | temp_day | **25~28** | **5~35** | 제주농기원 노지 오이 재배기술서(생육중지 임계) |
| 감자 | early | temp_day | 14~23 | **−3**~27 | 하한 −3℃ = 잎 냉해(Stegner 2019) |
| | tuber | temp_day | 23~24 | ~27 | 농사로 |
| | tuber | temp_night_min | 10~14 | ~**28** | 상한 28℃ = 야간 고온 괴경형성 중단(Zhang 2024) |
| 상추 | (전기간) | temp_day | **22~24** | **2.5~36** | P11 항온챔버 실측·생육정지 |

**위험구간 감쇠폭**(`risk_width`): `temp_day` = **2.219**. 전국 실측 산포도
`2.0 × robust_sd`이고 출처는 `outcomes/memory/indicator_dispersion.json`이다. PR #73에서
2.2408 → 2.219로 갱신했다(표본이 150 → 136지역으로 바뀜 — 문경 흥덕동 결함행 제외 등).

## 5. `outcomes/`(ML 이관본)와의 관계

같은 밭 점수를 두 곳에서 계산한다. **토양은 값이 일치해야 하는 계약이고 테스트로 고정했지만,
기온은 애초에 미러링 대상이 아니다** — 두 구현의 채점 구조가 다르다.

| | `outcomes/` | 백엔드 |
|---|---|---|
| 입력 | 작기 전체 월평균 **1개 값** | **월별** 평년 기온 12개 |
| 밴드 | 작물당 1개 | **생육단계별** |
| 목적 | "이 지역이 재배적지인가"(연 1회 판정) | "이 달에 이 밭이 어떤가"(히트맵 12칸) |

대조 결과 — 값이 겹치는 것도 있다:

| 작물 | `outcomes` (작기 평균 밴드) | 백엔드 | 판정 |
|---|---|---|---|
| 배 | 18.5~21.5 / 17~23 | `growing` 동일 | ✅ 일치 |
| 오이 | 25~28 / 5~35 | `growing` 동일 | ✅ 일치 |
| 상추 | 22~24 / 2.5~36 | 전기간 동일 | ✅ 값 일치 (채점월은 다름 — §미결정) |
| 사과 | 14.5~18.5 / 13.5~19.5 | 단계별 3개 | ⚠️ 구조 다름 |
| 감자 | 14~19.3 / 11.35~30 | early + tuber | ⚠️ 구조 다름 |

사과가 미반영인 것은 실수가 아니다 — 마이그레이션 `0015`가 "ARCCAS 단일 생육기 기준이 기존
단계별 값과 성격이 달라 반영하지 않는다"고 근거를 남겼다.

**계약 테스트(`test_guide_outcomes_contract.py`)를 토양에만 건 것이 이 때문이다.**

## 6. 화면에 나가는 정직성 표기

기온은 근사가 여러 겹이라 표기가 특히 중요하다(§18-4).

| 표기 | 내용 |
|---|---|
| `TEMP_SCALE_LIMITATION` | 카드의 낮 최고기온과 점수를 매긴 일 평균기온이 **다른 값**이고, 고온·냉해 기준은 원래 극값 기준이라 평균으로 매긴 점수는 극단적 위험을 약하게 본다 (단기) |
| `PARTIAL_DAY_LIMITATION` | 일부 날짜는 발표시각 이후 시간대만 반영됐고, 그 방향(평균은 높게·최고는 낮게)까지 명시 (단기) |
| `TEMP_DAY_LIMITATION` | 일 평균기온은 실측이 아니라 **월평년 근사**다 (장기) |
| `lapse_limitation()` | 감률 보정량·방향 + "밭 실측이 아니라 읍·면·동 대표점 기준" |
| 평년치 대체 문구 | 빌린 구역 수·이름·거리 범위 (예: "가까운 10곳 … 약 16~49km") |
| `OUTLOOK_MISSING_LIMITATION` | 3개월전망이 없어 보정 없이 평년치만 썼다 |
| 커버리지 문구 | 지침 지표 중 몇 개로 채점했는지, 빠진 지표 이름 |
| AWS 야간 저온 | 시드에 기록(화면 아님) — §3-2 |

**`dormant` 처리**: 그 달에 기상 지표가 하나도 채점되지 않았다면 점수·등급을 **숨긴다**.
토양 지표만으로 계산된 점수를 계절 적합도처럼 보여주던 버그가 있었다(겨울 사과가 100점 S).
