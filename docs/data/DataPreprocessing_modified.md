
## 작업 지시

너는 "농부의 행위(시비·유기물 투입 등) → 토양 화학성 3개 변수(pH, 유기물, 유효인산)의 변화량"을
예측하는 모델의 MVP 데이터셋을 구축해야 한다. 아래 순서와 스키마를 그대로 따라
공공데이터를 수집·정제하고, `data/` 디렉터리 아래에 정규화된 CSV 5개 + 코드북 1개를 만들어라.

**절대 하나의 통합 CSV로 합치지 마라.** 기상(일/월 단위)·화학성(연 단위)·토성(시간불변)은
시간 스케일이 달라서 합치면 중복 저장·이중 계산 위험이 생긴다. 반드시 아래 관계형 구조를 유지할 것.

```
01_soil_chemistry ──(region_code)── 02_soil_physical
       │
       └──(region_code + year/month)── 03_weather_monthly
04_treatment_reference : 별도 참조 (crop_code 기준)
05_soil_test_actual ──(region_code)── 01, 02, 03
```

## 변수 구조 (참고용 배경)

| 층위 | 변수 | 역할 |
|---|---|---|
| 처치변수 | 시비 종류·양·시기, 유기물 투입 | 개입 입력 |
| 종속변수 (Y) | pH, 유기물, 유효인산 | 다변량 출력 (서로 인과적으로 얽혀 있음) |
| 시간불변 조절변수 | 심토토성, 심토자갈함량, 경사도 | 지역별 반응 강도·속도 조절 |
| 시간가변 외생변수 | 기온, 강수량 | 무기화·용탈 속도에 영향 |

종속변수 간 인과 구조(모델링 시 고려): **유기물(배경) → pH → 유효인산**.
유기물은 CEC·완충능을 결정하는 배경 조건이고, pH는 유효인산의 가용도를 화학적으로 결정한다.
세 변수를 완전 대칭적 다중출력으로 다루지 말 것.

## 실행 순서 (이 순서대로 진행)

### 1단계 — `04_treatment_reference.csv` (정적, 가장 쉬움)
출처: 흙토람 OpenAPI **"작물별 비료 표준사용량 처방 정보"** + **"작물코드 목록 정보"**
```
crop_code, crop_name, std_nitrogen, std_phosphate, std_potash
```
용도: 실제 시비량과 비교해 "표준 대비 편차(%)"로 처치변수를 인코딩하는 baseline.

### 2단계 — `02_soil_physical.csv` (시간불변, 지역별 1회 수집)
출처: 흙토람 OpenAPI **"토양도 기반 토양특성 단면정보 V2"**
```
region_code, subsoil_texture_code, subsoil_gravel_code, slope_code
```
- region_code: 법정동 10자리 (조인 키)
- 각 코드는 흙토람 코드북 매핑이 필요하니 `99_codebook.csv`에 함께 정리할 것

### 3단계 — `01_soil_chemistry.csv` (종속변수, 시계열 핵심)
출처: 흙토람 OpenAPI **"농경지화학성 통계정보 V2"**
```
region_code, year, pH, organic_matter, available_p, k, ca, mg, silicic_acid
```
- pH, organic_matter, available_p만 MVP에서 사용. k/ca/mg/silicic_acid는 **삭제하지 말고 확장용으로 함께 저장**.
- **최소 10년치, 가급적 15~20년치** 수집 (조사가 4년 주기라 5년치로는 지역당 1~2개 관측점밖에 안 나와 시계열 학습이 사실상 불가능함). 20년치 먼저 시도 --> 실패시 15년치 시도 --> 실패시 10년치 시도
- 지역 커버리지: 최소 50개 읍면동(1차 프로토타입, 예: 경기도 한정), 이상적으로는 전국 150개 읍면동. 우선 150개 읍면동 단위로 시도한 이후, 데이터가 너무 크다고 판단될 경우, 50개 읍면동 단위로 파일을 생성할 것. 
  다음 3개 축이 골고루 섞이도록 층화표집할 것: 토성(사토/양토/식토 각 10개 이상), 기후대(남부/중부/북부), 경사도(평탄지/경사지).

### 4단계 — `03_weather_monthly.csv` (관측지점 매핑 필요, 가장 복잡)
출처: 농업기상정보서비스 **"농업기상 기본 관측데이터"** + **"농업기상 관측지점 상세정보"**
```
region_code, year, month, avg_temp, precipitation
```
- 관측지점 위경도를 법정동에 매핑하는 로직 필요(최근접 관측지점 또는 시·군 대표 지점).
- 습도/풍향/풍속/일조시간/일사량/토양수분은 MVP에서 제외.
- `01_soil_chemistry`의 관측 시점 **직전 5년치 월별 데이터**를 커버하도록 수집(나중에 "최근 3년 평균 강수량" 등 파생 변수 생성용).

### 5단계 — `05_soil_test_actual.csv` (선택, 있는 만큼만)
출처: 흙토람 OpenAPI **"토양검정 화학성 상세정보 V2"**
```
pnu, region_code, test_date, pH, organic_matter, available_p
```
- PNU(지번코드 19자리) 단위 실측치. 없어도 MVP 진행 가능하며, 나중에 GPR 사후분포 업데이트 검증용으로 쓴다.

### 6단계 — `99_codebook.csv` (진행하며 계속 정리)
```
code_type, code, label
```
- 심토토성/경사도/자갈함량/작물 코드 → 텍스트 라벨 매핑을 위 단계들을 진행하며 누적 정리.

## 절대 포함하지 말 것 (제외 데이터, 이유 포함)

| 제외 데이터 | 이유 |
|---|---|
| 토양적성등급 통계 | 화학성 결과의 파생변수 → 목표변수와 다중공선성/정보순환 |
| 비료사용처방 정보/체험 정보 | 화학성을 입력받아 처방을 출력 → 인과 방향이 반대 |
| 토양특성 통계정보 V2(면적 통계) | 필지 화학성 변화와 무관한 면적 분포 통계 |
| 친환경 인증 | 화학적 변화의 원인이 아닌 행정 라벨 |
| 농업유전자원/스마트팜/농업인건강안전/신기술보급사업 | 도메인(노지 토양 화학성)과 무관 |
| 기상청 단기예보, 날씨누리 | 미래 예보용. 과거 행위-반응 학습에는 불필요 |
| 작물별 토양적성 통계 V2 | 파생변수 이슈 동일 |

## 파일/포맷 규칙
- 모든 CSV는 UTF-8, 헤더 포함.
- 결측치는 빈 문자열이 아니라 **명시적 `NA` 문자열**로 표기.
- 각 CSV는 위 스키마의 컬럼 순서를 그대로 따를 것(조인 키인 `region_code`를 항상 첫 컬럼에 둘 것).

## 참고: 추후 모델링 방향 (데이터 수집 시 참고만 할 것, 지금 단계 작업 아님)

최종적으로는 **다중출력 가우시안 프로세스 회귀(Multi-Output GPR)**를 문헌 기반 사전분포와 함께 사용하고,
LightGBM Quantile Regression을 교차검증용 보조 모델로 병행할 계획이다. 따라서:
- 위 CSV들은 GPR의 입력(처치변수 + 시간불변 조절변수 + 시간가변 외생변수)과
  출력(pH, 유기물, 유효인산의 상관구조)을 그대로 지원하는 형태여야 한다.
- 데이터 수집 시 "절대 개수"보다 "다양성"(토성·기후대·경사도)을 우선할 것 — GPR은 소량 데이터에서도
  안정적으로 작동하지만, 다양성이 부족하면 커버되지 않은 조건에서 신뢰구간이 크게 벌어진다.
